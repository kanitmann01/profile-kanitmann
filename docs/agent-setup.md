# Wave E.1 — "Ask Kanit" agent setup (Cloudflare bindings)

This feature is a **server-side grounded RAG agent** over Kanit's projects,
articles, and experience. Two Cloudflare capabilities are required at runtime,
both consumed through the OpenNext worker's `env` (`getCloudflareContext().env`):

| Binding / var                    | Type                    | Used for                                                            |
| -------------------------------- | ----------------------- | ------------------------------------------------------------------- |
| `AI`                             | Workers AI              | Embed the query (`@cf/baai/bge-base-en-v1.5`) + generate the answer |
| `CF_TURNSTILE_SECRET`            | secret var              | Server-side validation of the client Turnstile token                |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` | public env (build-time) | Client-side Turnstile widget in `components/ask-panel.tsx`          |

There is **no client-side model** — the corpus is embedded at build time by
`scripts/generate-embeddings.ts` into `public/data/embeddings.json`, which is
bundled into the Worker. Only the user's query is embedded at runtime, server-side.

## 1. Create a Turnstile widget

1. Open https://dash.cloudflare.com/?to=/:account/turnstile.
2. **Add widget** → name it `kanitmann-ask` → hostname `kanitmann.com` (add
   `localhost` and your preview domain for local dev).
3. Copy the **Site Key** (public) and **Secret Key** (server-only).
4. For the local smoke test, either add your preview domain to the widget or
   use the Turnstile test keys (`1x00000000000000000000000000000000AA`
   site / `1x0000000000000000000000000000000AA` secret).

## 2. Wire bindings into the OpenNext worker

OpenNext surfaces Cloudflare bindings through `env` via
`getCloudflareContext({ async: true })` — the route reads `env.AI` and
`env.CF_TURNSTILE_SECRET`. Declare them in `wrangler.jsonc`:

```jsonc
{
  "$schema": "node_modules/wrangler/config-schema.json",
  "main": ".open-next/worker.js",
  "name": "profile-kanitmann",
  "compatibility_date": "2026-08-01",
  "compatibility_flags": ["nodejs_compat", "global_fetch_strictly_public"],
  "assets": { "directory": ".open-next/assets", "binding": "ASSETS" },
  "ai": { "binding": "AI" },
  "vars": { "CF_TURNSTILE_SECRET": "REPLACE_ME" },
}
```

Better: keep `CF_TURNSTILE_SECRET` out of the committed config and set it as a
Worker secret so it never lands in git:

```bash
npx wrangler secret put CF_TURNSTILE_SECRET
```

`AI` is a real binding (no secret). The binding type augmentation lives in
`types/cloudflare-env.d.ts` (`env.d.ts` is gitignored — generated by
`npm run cf-typegen`).

### Local `next dev`

`next.config.mjs` already calls `initOpenNextCloudflareForDev()`, so with the
`ai` binding above, `env.AI` resolves against your real Workers AI account
(`wrangler` must be authenticated). The Turnstile secret resolves from
`vars`/`--var`.

- No `CF_TURNSTILE_SECRET` configured → Turnstile is **skipped** (dev mode).
- No `AI` binding / empty `embeddings.json` → the API streams a static
  "coming soon" message instead of erroring, so the widget and site always work.

## 3. Build-time embeddings

```bash
CLOUDFLARE_API_TOKEN=... CLOUDFLARE_ACCOUNT_ID=... npm run generate:embeddings
```

- Requires a Cloudflare API token with `Workers AI:Run` permission.
- Output: `public/data/embeddings.json` — bundled into the Worker via the
  static import in `lib/ask/rag.ts`. Embeddings are quantized to 4 decimals to
  keep the bundle reasonable (~630KB for the current corpus).
- **Without credentials the script still succeeds** (build never blocks): it
  writes deterministic placeholder vectors and logs a warning. Regenerate with
  real credentials for semantic retrieval.

## 4. Env vars for the Next.js build

```bash
NEXT_PUBLIC_TURNSTILE_SITE_KEY=<site key>  # client widget
NEXT_PUBLIC_SITE_URL=https://kanitmann.com # already used repo-wide
```

## 5. Behavior notes / tradeoffs

- **Rate limit** is an in-memory LRU (10 req/hr/IP) in `lib/ask/rate-limit.ts`.
  It persists for the lifetime of one Worker isolate — per-region enforcement,
  reset on redeploy. Fine for a portfolio; move to KV/D1 if traffic demands it.
- **Models**: `@cf/meta/llama-4-scout-17b-16b-instruct` with a fallback to
  `@cf/qwen/qwen1.5-0.5b-chat` when Scout is rejected (free-tier). The swap is
  logged server-side.
- **Streaming**: the route emits SSE events — `citations` (top-5 chunks) →
  `delta` (token text) → `done` (or `error`). The client parses them in
  `components/ask-panel.tsx`.
- **Reduced motion**: the panel transition collapses to an opacity crossfade.
- **Mobile**: the panel renders as a full-screen sheet; desktop is a right
  slide-over. No floating bubble anywhere.
- **Bundle**: the widget loads lazily (first ⌘J / ASK click), so the initial
  client bundle is unchanged apart from a few bytes.

## 6. Smoke test

```bash
npm run dev
curl -i -X POST http://localhost:3000/api/ask \
  -H 'Content-Type: application/json' \
  -H 'X-Turnstile-Token: test' \
  -d '{"message":"What did Kanit build at Ericsson?"}'
```

Expect an SSE stream whose `citations` event references the Ericsson chunk and
whose answer mentions migrating 2,000+ servers to GCP. Requires the `AI`
binding wired as above (without it, you get the static "coming soon" stub).
